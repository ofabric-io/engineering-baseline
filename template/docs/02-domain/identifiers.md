# Identifiers

## Purpose

How entities are identified internally and publicly, and what an identifier must never do. The project's own type prefixes and resource list are project-defined; this document fixes the shape.

## Parameters

| Parameter | Answer | Default | Trade-off |
| --- | --- | --- | --- |
| `internal_id_format` | [[internal_id_format]] | UUIDv7 (RFC 9562) | time-ordered and index-friendly; a sequential integer leaks volume and order |
| `public_id_format` | [[public_id_format]] | type-prefixed opaque string, e.g. `<prefix>_<encoded>` | self-describing in logs and support tickets; a raw UUID is not; the encoding should be case-insensitive with unambiguous characters |
| `natural_keys_as_primary_keys` | [[natural_keys_as_primary_keys]] | forbidden | natural keys change; identifiers must not |
| `type_prefixes` | [[type_prefixes]] | one short unique prefix per publicly addressable resource, listed in the project's table below | a prefix per resource aids debugging; sub-resources reached only through a parent can go without |

## Rules

### Internal identifiers

- **R1.** Every persisted entity MUST have an identifier in `internal_id_format`, generated by the application, never by the caller.
- **R2.** An identifier MUST NOT encode information: no isolation unit, no date segment, no countable sequence. A time-ordered random format (such as the default) is not a date segment, because nothing is meant to be read back out of it; a per-scope ordering counter is permitted only as R15 allows.
- **R3.** An identifier MUST NOT be reused or recycled, even after the entity is gone.
- **R4.** A value governed by `natural_keys_as_primary_keys` MUST NOT be a primary key if that parameter says forbidden; a natural key is stored as an attribute with a uniqueness constraint.
- **R5.** A storage-private surrogate key, if one exists, MUST NOT appear in an interface response, URL, log, trace or event, and MUST NOT be a foreign-key target.

### Public identifiers

- **R6.** A publicly addressable resource MUST expose an identifier in `public_id_format`, carrying the resource's type prefix from the project's prefix table.
- **R7.** A raw internal identifier MUST NOT be exposed in an interface response, URL or event.
- **R8.** A type prefix MUST be unique within the project and MUST NOT be changed once published.
- **R9.** A public identifier MUST be validated for its prefix before use; the wrong type MUST be rejected, not looked up.
- **R10.** A correlation identifier that is not a resource (for example one per request) MAY carry its own prefix, MUST NOT be persisted as a resource key and MUST NOT be addressable.
- **R11.** One codec MUST be the only place a public identifier is encoded or decoded.

### Typing and references

- **R12.** Where the language supports it, each identifier kind MUST be a distinct type so that one kind cannot be passed where another belongs.
- **R13.** A caller-supplied reference to an entity MUST be treated as untrusted text: length-bounded, validated, unique only within its owner's scope, and never interpolated into a query or a log message.
- **R14.** A caller-supplied reference MUST NOT be used as an idempotency key (`08-reliability/concurrency-and-idempotency.md`); it identifies an entity, a key identifies one attempt.
- **R15.** A per-scope ordering counter (for example a generation number) MAY be stored as an ordinary attribute for ordering or optimistic concurrency; it MUST NOT be an identifier, be exposed as one, or be a foreign-key target.

## Enforcement

| Rule | Mechanism | Status |
| --- | --- | --- |
| R1, R3 | Entity base type or schema convention (chosen in `13-technology/`); review | ⬜ scheduled |
| R2 | Review; time-ordered random formats carry no business data by construction | ❌ review-only |
| R4 | Schema review of primary keys | ⬜ scheduled |
| R5 | Interface-schema check that no private key is serialised | ⬜ scheduled |
| R6, R7 | Interface-schema review; contract tests | ⬜ scheduled |
| R8 | Prefix table in this document is the register; duplicate-prefix check | ⬜ scheduled |
| R9, R11 | The single codec validates prefix before decoding; property test of round-trip | ⬜ scheduled |
| R10 | Review | ❌ review-only |
| R12 | Compiler or type checker where the stack supports distinct types | ⬜ scheduled |
| R13 | Boundary validation; parameterised queries | ⬜ scheduled |
| R14 | Review; idempotency mechanism reads only its own header or field | ❌ review-only |
| R15 | Review; schema check that no counter is a key or foreign-key target | ❌ review-only |

## AI guardrails

```text
Identifiers carry NO information and are never reused. Never use a natural key as a primary key.
Never expose a raw internal id or a storage-private surrogate key.
Public ids carry the type prefix from the project's table. ALWAYS validate the prefix before use.
Use the one codec; never encode or decode an id by hand.
A caller-supplied reference is untrusted text and is NOT an idempotency key.
An ordering counter is an attribute, never an identifier.
Do not invent a new prefix; add it to the table first.
```
